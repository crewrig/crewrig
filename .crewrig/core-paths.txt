# Core-layer paths — machine-readable manifest for sync-from-upstream.sh
# Maintained by upstream CrewRig. Any PR that adds, removes, or reclassifies
# a core-layer path in docs/layers.md MUST update this file in the same diff.
#
# Format: <path>[<TAB><policy>]. Blank lines and lines starting with # are
# ignored. The policy column is optional; an absent column defaults to
# `strict` (backward-compatible with the original one-path-per-line form).
#
# Policies (spec 0020):
#   strict         Upstream-owned. A local modification halts the sync.
#   adopt-on-edit  Upstream-owned until the adopter modifies it, then
#                  preserved permanently (never overwritten, never aborts).
#   regenerable    Upstream-owned content the component build regenerates
#                  (spec 0199 R42) — today, the four compiled agent output
#                  trees. Restores exactly as strict restores (including the
#                  spec-0064 orphan cleanup), but never aborts the sync on a
#                  local divergence: under an organization-level model-mapping
#                  override, the divergence is the build's own correct
#                  output, and this policy exists because the sync cannot run
#                  the build to tell the two apart. Each restored member
#                  whose local content had diverged is reported.
#   excluded       Org-owned. Never guarded, never restored, never touched.
#
# Nested exclusion: an `excluded` entry nested under a `strict`/`adopt-on-edit`
# parent (e.g. `specs/org` under `specs`, `.crewrig/.synced-markers` under
# `.crewrig`) is carved out of BOTH the parent's dirty guard and its restore
# via a `:(exclude)` git pathspec, so org content under a core parent can
# never abort the sync nor be overwritten.
#
# `.crewrig/.synced-markers/` holds per-path last-synced upstream blob SHAs
# (adopt-on-edit state). It is committed by the adopter (durable across a
# fresh clone) but never synced from upstream — it is machine-managed; do
# not hand-edit.

# `.crewrig/spec-id-carrier` names the git ref namespace this repository uses to
# hold spec-id reservations (spec 0112). Upstream ships a default value, but the
# value encodes which namespace THAT ADOPTER'S REMOTE accepts — something
# upstream cannot know and has no business overriding — so it is `excluded`: an
# adopter whose remote refuses the default changes it once and the sync never
# guards, restores, or aborts on it. `adopt-on-edit` would NOT work here: the
# only nesting mechanism this manifest defines and sync-from-upstream.sh
# implements is an `excluded` carve-out (see Nested exclusion above), nothing
# performs most-specific resolution, so a nested `adopt-on-edit` member would be
# governed by its `strict` parent and the adopter's own edit would halt the sync.
# The trade-off is symmetric and permanent: upstream can never update the value
# afterwards either. Distribution is unaffected — the file is committed in the
# tree a fork clones; `excluded` governs synchronisation only.
.crewrig/spec-id-carrier	excluded
