# Path-ownership exemptions (spec 0147 delta-01, R14-R17, R24).
#
# Format: one entry per line, `<glob><TAB><reason>` -- a real TAB character
# separates the glob from the reason. Blank lines and lines starting with `#`
# are ignored. An entry with an empty reason, or whose glob matches no tracked
# file (a stale entry), fails `scripts/check-path-ownership.ts`; an entry
# whose every match is also owned is reported as redundant without failing.
#
# Glob syntax is the one the checker implements: `*` (does not cross `/`),
# `**/` (zero or more directories), and a trailing `**`. Any other
# syntax, `?` and `+` included, is rejected. See docs/ci-reference-format.md, "Path ownership and
# the exemption lists".
#
# R17 -- use an exemption only for a file that no check exercises, or that a
# capability with no `paths:` filter exercises on every change (name that
# capability in the reason). Never use it to silence a file that a
# `paths:`-filtered capability exercises: add the glob to that capability's
# `paths:` in ci/ci-capabilities.yml instead.
#
# Organization overlay (R24): an adopting organization lists its own files in
# ci/org/path-ownership-exemptions.txt (same format, same rules, read in
# addition to this core list; absent is not an error). The overlay is itself a
# tracked file, so it MUST list itself on its first line (D7):
#   ci/org/path-ownership-exemptions.txt<TAB><reason>
#
