# Extension release-note heading format without doubled prefix

## Intent

Extension release notes generated by the monorepo release pipeline render
clean top-level headings without a doubled `v` prefix (`# v<ext>-v<version>`),
formatting the heading as `<ext> v<version>` on both GitHub and GitLab
forge targets.

## Requirements

1. The release-note generation in `scripts/lib/monorepo-release-lib.sh` and the
   GitLab template `scripts/lib/release-notes/gitlab-template.hbs` SHALL format
   extension release note headings without a duplicated `v` prefix.
2. Both the GitHub release note path and the GitLab-vendored template SHALL produce
   consistent heading conventions for extension release notes.
3. The regression test suite `scripts/tests/test-monorepo-release-notes.sh` SHALL
   assert that the rendered release note heading matches the expected format and
   does not contain a doubled `v` prefix (e.g. `v<ext>-v<version>`).

## Scenarios

**Scenario:** Extension release notes render single prefix

Given an extension release for `notes-fixture` at version `1.0.0`
When the release notes are generated for GitHub or GitLab
Then the top-level heading does not start with `# vnotes-fixture-v` and renders the extension name and version cleanly.

**Scenario:** GitLab template compare link works cleanly

Given an extension release on GitLab with a previous release tag
When the release notes are generated
Then the compare link uses valid tag references.

## Out of scope

- Changing root framework release note formats.
- Modifying tag formats or version calculation in `semantic-release-monorepo`.
